# RAG 混合检索系统设计

## 一、为什么需要混合检索

企业知识库既包含自然语言说明，也包含技术术语、错误码、函数名和配置项。

单一检索方法难以同时处理这些内容。

Dense Retrieval 擅长语义相似性检索，BM25 擅长词项匹配，因此可以组合两种检索方式。

## 二、Dense Retrieval

Dense Retrieval 使用 Embedding 模型把文本转换成向量，再比较查询向量与文档向量之间的相似度。

例如，用户询问“如何防止智能体一直重复使用工具”，知识库文档可能写的是“通过最大执行轮数限制 Agent Loop”。

虽然两个句子的词汇并不完全相同，但语义接近，向量检索可能找到对应文档。

Dense Retrieval 的局限是：对某些精确标识符、版本号和特殊错误码，语义相似不一定意味着内容正确。

## 三、BM25 关键词检索

BM25 是一种基于词项匹配的检索排序方法，主要考虑词频、逆文档频率和文档长度等因素。

当用户查询精确函数名、配置字段、文件路径或者错误码时，BM25 往往具有优势。

例如，查询具体的 Python 函数名时，包含相同函数名的文档通常比仅在语义上相关的文档更有价值。

但是，BM25 对语义改写的适应能力有限。如果用户的问题和文档采用不同表达，可能无法有效匹配。

## 四、RRF 排名融合

Reciprocal Rank Fusion，简称 RRF，用于融合不同检索器的排序结果。

RRF 不直接比较 Dense 相似度和 BM25 分数，而是根据文档在各个排序列表中的名次累加贡献。

常见计算形式为：

RRF(d) = sum(1 / (k + rank_i(d)))

其中 rank_i(d) 表示文档 d 在第 i 个检索器结果中的排名，k 是平滑常数。

RRF 的优势是不同检索方法不需要使用相同的评分尺度。

如果一份文档同时在 Dense 和 BM25 结果中排名靠前，它通常能够获得较高的融合分数。

RRF 主要解决的是多路检索结果融合问题，并不直接判断文档是否足以回答用户问题。

## 五、Rerank 重排序

Rerank 在初步召回之后，对候选文档重新进行相关性排序。

例如，系统先通过 Dense 和 BM25 检索，再使用 RRF 得到前十个候选 Chunk，随后让 Rerank 模型判断这些候选与用户问题的相关程度。

Rerank 与 RRF 的区别在于：

RRF 主要依据检索排名进行融合。

Rerank 则进一步评估问题与候选内容之间的相关性。

Rerank 可能提高排序质量，但通常也会增加延迟、模型调用次数和 Token 消耗。

是否启用 Rerank，需要通过统一评测集比较准确率和运行成本。

## 六、Query Rewrite 查询改写

Query Rewrite 在检索前改写用户问题，使其更适合知识库检索。

例如，用户询问“怎么避免它一直调用函数”，可以改写成“Agent Loop 如何通过 max_steps 限制工具调用”。

但查询改写可能引入用户原本没有表达的条件，因此不应该无条件信任改写结果。

Query Rewrite 与 Rerank 位于不同阶段：前者通常发生在检索之前，后者发生在候选召回之后。

## 七、检索效果评测

检索评测需要提前标注正确的证据 Chunk，称为 Gold Chunk。

Hit@1 表示排名第一的检索结果是否命中正确证据。

Hit@5 表示前五个结果中是否包含正确证据。

MRR 使用第一个正确结果的倒数排名来衡量排序质量。

例如，正确证据排在第二名时，单个问题的倒数排名为 0.5。

评测 Dense、BM25、RRF 和 Rerank 时，应使用相同的语料、问题和 Gold 标注。

除检索质量外，还应记录检索延迟，以及需要调用大模型时的 Token 消耗。

## 八、检索与回答可靠性的区别

检索排名较高不代表文档一定能够回答用户问题。

Answerability 用于判断当前证据是否足以支持回答。

Grounding 用于检查最终回答中的事实是否能够由证据支持。

因此，一个完整的知识库问答系统不仅需要提高检索准确率，还应该在证据不足时拒绝编造答案。
